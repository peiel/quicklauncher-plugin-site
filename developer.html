创建你的第一个插件

创建一个目录，放入以下两个文件。本例将输入的文本原样显示并复制；无参数时可使用前台应用中选中的文本。

manifest.json

{
  "id": "com.example.echo",
  "name": "文本示例",
  "description": "显示并复制文本",
  "keyword": "echo",
  "version": "1.0.0",
  "author": "Example",
  "runtime": "python",
  "entry": "main.py",
  "input": "arguments",
  "acceptsSelectedText": true
}

main.py

import json
import sys
import unicodedata

request = json.load(sys.stdin)
text = request.get("arguments", "").strip()
if request.get("version") != 1:
    result = {"version": 1, "action": "error", "text": "不支持的协议版本"}
elif not text or len(text) > 200 or any(unicodedata.category(c) == "Cc" for c in text):
    result = {"version": 1, "action": "error", "text": "请输入不超过 200 字的单行文本"}
else:
    result = {"version": 1, "action": "copyAndShow", "text": text}
print(json.dumps(result, ensure_ascii=False))

在该目录运行下面的命令，预期输出包含 copyAndShow 和 Hello 的 JSON。此命令只运行脚本，不会操作 QuickLauncher 或剪贴板。

printf '%s\n' '{"version":1,"arguments":"Hello"}' | python3 main.py

接着在 QuickLauncher 的“设置 → 插件 → 发现插件”点击“导入插件…”，选择这个目录。查看代码并确认导入后，输入 echo Hello，选择插件执行。支持安装后自动启用的版本会直接启用并打开“已安装”；旧版需在“已安装”中启用。Python 需要本机已有可用的 Python 3；可在“运行环境”中配置解释器。

示例声明了选区能力：只输入 echo 并执行时，应用会尝试读取唤起前的选中文字。没有这项需求时，请删除 acceptsSelectedText。

插件清单

manifest.json 是插件目录根部的 UTF-8 JSON 文件。以下字段除标注可选外均为字符串且必填。

字段说明
id唯一标识，最多 120 字符；以英文字母或数字开头，之后可用字母、数字、点、下划线、连字符。建议使用反向域名，发布后保持稳定。
name / description显示名称与功能说明；名称不能为空。
keyword触发词，1–32 个英文字母、数字、下划线或连字符，大小写不敏感。用户可修改；相同触发词的插件不能同时启用。
version / author版本与作者信息。建议发布版本与 Git 标签保持一致。
runtimeshell、python、ruby、applescript 或 executable。前四种可在应用中配置解释器绝对路径；executable 的入口需有执行权限。
entry入口文件的相对路径，必须存在；不使用绝对路径或 .. 路径段。应用以插件目录作为工作目录。
input（可选）arguments 接收触发词后的文本；passwordLength 接收密码长度；不声明时仅匹配触发词。
acceptsSelectedText（可选）布尔值。设为 true 时必须同时声明 input: "arguments"；无参数执行时才尝试读取选区。
passiveTrigger（可选）被动触发规则对象；必须同时声明 input: "arguments"。匹配输入时脚本自动运行并预览结果。
previewOnKeyword（可选）布尔值。设为 true 后，输入完整触发词时自动运行插件并预览结果；支持参数的插件也可在触发词后附加参数。不声明或为 false 时保留普通触发方式。
sourceURL（可选）插件源码地址。

触发词预览

在插件清单中设置 "previewOnKeyword": true 后，启用的插件在用户输入完整触发词时自动运行；例如密码插件可将 keyword 设为 pwd、input 设为 passwordLength。输入 pwd 使用默认长度，输入 pwd 32 则使用本次指定的长度。用户修改触发词后，以修改后的触发词为准。

脚本返回 copy 或 copyAndShow 时，应用会在面板中显示文本；用户选中结果并按回车后，复制当前显示的同一结果并关闭面板，不会再次运行脚本。预览文本最多 200 字符且不得含控制字符。支持多项预览的新版本还允许返回 list，如下文所述；其他动作不会作为预览执行。预览时不会读取其他应用的选中文字。

显示与信任：触发词预览会明文显示结果，即使脚本返回 copy 也包括密码等敏感内容。应在插件说明和审核中明确告知用户，避免记录或上传结果，并只启用信任的代码。旧版 QuickLauncher 不支持此字段，仍需选中插件并执行；需要即时预览的用户应使用支持该能力的新版本。

被动触发规则

在插件清单中添加如下 passiveTrigger，可在搜索输入由允许的字符组成、且每组必需字符至少出现一个时触发。例如，规则可匹配 1+1；123 缺少运算符、1+1a 包含不允许的字符，均不会触发。

{
  "type": "characterSet",
  "allowedCharacters": "0123456789 +-*/().×÷",
  "requiredCharacterGroups": ["0123456789", "+-*/×÷"]
}

allowedCharacters 和每个必需字符组须为 1–128 个 Unicode 字符，不得包含控制字符或换行；requiredCharacterGroups 须包含 1–8 组，每组字符都必须属于允许的字符。匹配输入最多 256 UTF-8 字节。

用户如何控制被动触发

用户可在“设置 → 插件 → 已安装”，打开对应插件的“设置”，在“被动触发”中查看允许字符和必需字符组，并独立开关被动触发。没有单独设置时，声明此规则的插件默认开启被动触发；插件整体也必须启用，匹配时才会自动运行。关闭被动触发后，原有触发词仍可使用。

开关选择会保存在本机，重启应用或更新插件后仍会保留。支持安装后自动启用的 QuickLauncher 版本会在用户审核确认安装后启用插件；旧版安装后需手动启用。支持保留启用状态的版本在用户审核确认更新后会保留更新前的启用状态，旧版更新后仍需重新启用。被动开关本身不会替代插件启用和更新审核。

自动运行与隐私：输入符合规则时，应用会为最多三个匹配且被动触发已开启的已启用插件运行预览，不必先选中结果。脚本会收到匹配的文本，仍以当前用户身份执行，可以访问文件和网络；请避免产生副作用、读取或上传不必要的数据，并向用户说明用途。

标准输入与输出

未声明触发词预览的插件在用户选择触发词结果后启动；启用 previewOnKeyword 后，匹配触发词时可自动启动并预览。已启用插件的被动触发开关开启时，匹配规则的输入也可启动预览。应用通过标准输入发送一个 JSON 请求；脚本向标准输出写一个完整 JSON 对象，并以成功退出码结束。不要在标准输出混入日志；标准错误不会展示或记录。

{"version":1}
{"version":1,"arguments":"Hello"}
{"version":1,"passwordLength":24}

请求始终包含协议 version: 1。arguments 是触发词后的原始文本，最多 1024 UTF-8 字节；被动触发时是匹配的完整输入，最多 256 UTF-8 字节。passwordLength 为 8–128 的整数，用户未临时指定时使用应用设置的默认长度。按清单声明选择输入类型；仅声明 arguments 的插件可以接收选区。

被动运行只接受 copyAndShow 作为预览，用户选中结果并确认后才复制；其他动作不会在预览阶段执行。被动匹配时不会读取其他应用的选中文字。

返回 action行为与限制示例
copy普通执行时复制 text 且不显示；启用触发词预览时会明文显示结果，回车后复制并关闭。{"version":1,"action":"copy","text":"value"}
copyAndShow普通执行时复制并显示 text，面板保持打开；触发词预览时先显示，回车后复制并关闭。显示敏感结果需明确告知用户。{"version":1,"action":"copyAndShow","text":"9"}
list仅用于已声明 previewOnKeyword 的触发词预览，提供多项可复制结果；用户选择后按回车复制对应项并关闭面板。{"version":1,"action":"list","items":[{"title":"2026-11-15","subtitle":"ISO 日期","text":"2026-11-15"}]}
message显示短暂提示。{"version":1,"action":"message","text":"完成"}
error显示错误并保持面板。{"version":1,"action":"error","text":"输入无效"}
scheduleReminder由应用安排一次系统通知；seconds 为 1–2,592,000 的整数（最长 30 天）。{"version":1,"action":"scheduleReminder","text":"喝水","seconds":600}

除 list 外，响应的 text 均不能为空；copyAndShow、error 和提醒文本最多 200 字符且不能含控制字符，提醒文本不能仅为空白。触发词预览中的 copy 文本同样最多 200 字符且不能含控制字符。list 的 items 必须包含 1–10 项；每项的 title、subtitle 和 text 均为必填字符串，不能仅为空白、不能含控制字符或 Unicode 换行符（包括 U+2028、U+2029），且各不超过 200 字符。用户上下选择后按回车，应用复制对应项的 text 并关闭面板，不会重新运行脚本；普通执行或被动触发返回 list 不会复制或执行副作用。多项预览需要包含该能力的新版本 QuickLauncher，官网发行版 1.4 及更早版本不支持。脚本执行超时为 5 秒，标准输出上限 65,536 字节；超限或 JSON 无效将被拒绝。

列表项可选提供稳定的 id，如 datetime_chinese。ID 须为 1–64 个 ASCII 字符，以字母或数字开头，其余只能是字母、数字、点、下划线或连字符；同一列表内不得重复，非法或重复的 ID 会使整个列表被拒绝。使用固定 ID，不要将日期、时间、查询或其他用户数据放入 ID。支持记忆选择的新版本在成功复制后，只在本机按插件保存所选 ID，下次将匹配项排在第一位；其余项保留原顺序，保存的 ID 不存在时显示原顺序。卸载插件或清除使用与查询记录时会删除相应选择记录。官网发行版 1.5 会忽略 ID 并保留原顺序。

应用提供的能力

文本参数

声明 input: "arguments"，执行 keyword 参数 时获得文本；应用不会把脚本查询写入使用历史。

被动匹配

声明 passiveTrigger 后，启用插件和被动触发时，匹配输入会自动运行脚本并接收输入；使用 copyAndShow 返回预览，用户确认后复制。用户可独立关闭被动触发，保留触发词执行。

触发词预览

声明 previewOnKeyword 后，输入触发词即运行并显示结果；回车复制当前显示的内容并关闭面板。该能力需要新版 QuickLauncher，显示敏感内容前应告知用户。

读取选中文字

额外声明 acceptsSelectedText: true。只有用户无参数执行插件时才读取唤起前应用的选区，作为 arguments 传入。需用户授予辅助功能权限，目标应用也须提供选区；失败时用户可直接输入。不会模拟复制按键或读取剪贴板。

显示或复制结果

返回 copy、copyAndShow、message 或 error；新版还支持触发词预览中的多项 list。由应用处理界面和剪贴板，剪贴板内容可能被有权限的其他应用读取。

定时提醒

返回 scheduleReminder，应用向系统申请一次性通知；首次使用时可能请求通知授权。显示受系统通知设置和专注模式影响，脚本无需后台等待。

权限与信任：脚本以当前用户身份运行，不受 QuickLauncher 沙箱限制，可自行访问文件、网络或其他应用；AppleScript 控制其他应用可能需要系统自动化权限。请在说明中明确数据用途，不上传敏感数据，不把凭证写入插件包。选区读取需由用户自行授权，标记为安全输入的控件不会读取。应用未提供任意插件访问书签、查询历史或密码的宿主 API。

本地安装与调试

  1. 在“设置 → 插件 → 发现插件”选择“导入插件…”，选包含清单的目录。
  2. 查看代码并确认导入；支持自动启用的版本会在安装后启用插件并打开“已安装”，旧版需检查文件后手动启用。若声明选区能力，需由用户按需在“设置 → 权限”中自行管理系统授权。
  3. 输入完整触发词和可选参数，选中结果执行；声明被动触发时也可输入匹配内容预览并确认复制。可在设置中调整触发词及 Python、Ruby、Shell 或 AppleScript 解释器路径。
  4. 导入时会复制文件，源目录改动不会自动同步；修改已安装副本后，需检查代码并重新启用。要重新导入相同 ID，需先删除旧副本；请留意保存自定义设置。请使用新版 QuickLauncher 以支持本页介绍的协议。

测试被动触发时，可在插件“设置 → 被动触发”中依次验证：开启时匹配输入显示预览；关闭后匹配输入不再自动运行，原触发词仍可执行；再次开启后预览恢复。另用不匹配的输入检查规则不会误触发。

发布到 GitHub

发布公开仓库与正式 Release 后，即可在应用内用 owner/repo 查找并审查安装。发布前确认插件文件不包含密钥或个人数据，并使用已经测试的 Git 提交打包。

如果已经通过本地导入安装了相同 ID，应用不会直接把该副本切换为 GitHub 来源。请先保存需要保留的自定义设置并删除本地副本，再从 GitHub 安装；也可以在隔离的测试环境中验证 GitHub 安装。
  1. 在 GitHub 创建一个空的公开仓库，将插件提交并配置 origin 指向它。新建仓库可在插件目录中执行以下命令，将 OWNER/REPO 替换成自己的仓库名；已有 Git 仓库可跳过初始化和添加已有 remote 的步骤。
git init -b main
git add manifest.json main.py
git commit -m "Add plugin"
git remote add origin https://github.com/OWNER/REPO.git

可添加 quicklauncher-plugin topic 作为仓库标记；应用内未收录仓库使用完整 owner/repo 查找。

  1. 下载 插件打包工具（MIT 协议，许可证；需要 Python 3.9+），创建并推送标签，从标签导出文件并打包。下面命令在插件 Git 仓库根目录执行：
git tag v1.0.0
git push origin main v1.0.0
WORK_DIR="$(mktemp -d "${TMPDIR:-/tmp}/quicklauncher-release.XXXXXX")"
mkdir "$WORK_DIR/source"
git archive v1.0.0 | tar -x -C "$WORK_DIR/source"
curl -fsSL https://plugin.quicklauncher.flyee.tech/tools/package_github_plugin.py -o "$WORK_DIR/package_github_plugin.py"
python3 "$WORK_DIR/package_github_plugin.py" "$WORK_DIR/source" "$WORK_DIR/my-plugin.quicklauncher.json"

如果标签已存在，请跳过创建标签的命令。替换 main 为仓库的实际分支名。工具拒绝 .git、符号链接、特殊文件、常见凭证文件、无效清单及超限内容，不会覆盖现有输出；插件最多 1000 个文件、原始内容总计不超过 10 MB、JSON 资产不超过 16 MB。自动检查不能识别所有敏感信息，请逐项检查它列出的文件。

在 GitHub 创建正式 Release 并上传唯一一个以 .quicklauncher.json 结尾的附件。例如，安装 GitHub CLI 并登录后：

gh release create v1.0.0 "$WORK_DIR/my-plugin.quicklauncher.json" \
  --repo OWNER/REPO --verify-tag --title v1.0.0 --notes "首个版本"

将 OWNER/REPO 替换为你的公开仓库。源码 ZIP 不能代替该附件。应用会显示仓库、标签、提交和资产摘要并在用户确认后安装；摘要一致不证明作者身份或资产确实由该提交构建。后续使用新标签发布更新，用户审核变更后确认。

想提供直接打开应用的链接，可使用 quicklauncher://install?repo=OWNER%2FREPO，将仓库名替换为你的值。链接只触发查找和审核，不能绕过用户确认。

申请目录收录

GitHub 仓库可先通过 owner/repo 安装；添加 topic 不会自动出现在展示站。要申请收录，请通过 官网仓库提交 Pull Request，插件源码和 Release 仍保留在你自己的 GitHub 仓库。

  1. 准备发布：按照发布到 GitHub创建公开仓库和正式 Release，上传唯一的 .quicklauncher.json 附件。确认清单、入口、版本和运行环境可用，并说明插件用途、触发词及需要的权限。
  2. Fork 并创建分支：在 GitHub Fork 官网仓库，从最新的 main 创建分支，将你的 OWNER/REPO 添加到官网仓库的 catalog-repositories.json。不要手动修改 catalog.json，它由同步任务生成。
  3. 添加网站卡片：在 index.html 的插件列表中添加卡片，填写唯一的卡片 ID、搜索关键词、插件名称、用途、运行环境、源码链接和安装链接；data-repository 必须与白名单中的仓库名一致。版本标签使用 版本待同步，不要写死版本号。
  4. 检查并提交：更新 tests/catalog.test.js 与 tests/catalog-versions.test.js 中的卡片、数量及版本期望，在官网仓库运行 node tests/catalog.test.js、node tests/catalog-versions.test.js 和 node tests/developer.test.js。向官网仓库的 main 发起 PR，说明仓库、Release、功能、测试方式和所需权限。

维护者会审核 PR 和插件内容；当前仓库没有专门针对插件 PR 的自动安全审查，提交不代表自动收录。合并后网站随主分支更新，GitHub Actions 约每四小时同步白名单中的最新正式 Release、标签提交和资产摘要，也可由维护者手动触发。同步或部署可能延迟或失败；目录更新前，新卡片的版本可能显示“版本暂不可用”。网站卡片从目录读取版本，名称和介绍仍需维护。

收录的标签须以英文字母或数字开头，后续仅使用字母、数字、点、下划线或连字符（总长最多 200）；附件名也须以字母或数字开头、仅含上述字符，并以 .quicklauncher.json 结尾。目录快照超过 48 小时后，应用会暂停使用该目录安装或更新；目录不可用时，按仓库名查找也可能暂时不可用。

用户通过网站进入 QuickLauncher 后仍须审查并确认安装；支持自动启用的版本确认后启用插件，旧版安装后需手动启用。审核和摘要匹配不代表作者身份或代码安全已获验证。

完整验证与常见问题

以下步骤参考文本统计插件从开发到收录的过程。按实际需求选择测试；记录已完成的结果，并区分脚本测试、隔离环境测试和真实应用操作。

1. 脚本与本地安装

  1. 检查清单、入口、运行时和依赖；用标准输入发送协议 JSON，验证正常结果、空输入、无效协议版本和适用的边界。文本插件应考虑中文、组合字符、换行和 1024 UTF-8 字节限制；不要把字节数与字符数混为一谈。
  2. 在测试用 QuickLauncher 环境导入插件，审查后启用，验证触发词、直接输入、结果显示和复制。若声明选区能力，还须在其他应用选中文字，再唤起 QuickLauncher，只输入触发词并执行；按需在“设置 → 权限”自行授予辅助功能权限。模拟向脚本传入文本不能证明系统选区读取成功。
  3. 检查无选区、权限未授予或目标应用不提供选区时的提示。涉及通知等能力时，还需在真实应用中检查对应权限和系统行为；未实际操作的项目应标明未验证。

例如文本统计插件可输入 textstats hello world，也可先在其他应用选中 hello world 再执行 textstats；两种方式均应显示字符 11、不含空白 10、词组 2、行 1、UTF-8 字节 11。

2. GitHub 发布与安装审核

  1. 从已测试的 Git 标签导出并打包，检查打包工具列出的文件，不包含凭证或私人数据。确认清单版本、标签和正式 Release 相对应，且 Release 只有一个 .quicklauncher.json 附件。
  2. 比较本地包的 SHA-256 与 GitHub Release 附件的 digest。例如完成上面的打包步骤后，将下面的仓库名和标签替换成自己的值：
shasum -a 256 "$WORK_DIR/my-plugin.quicklauncher.json"
gh api repos/OWNER/REPO/releases/tags/v1.0.0 --jq '.assets[] | {name, digest}'

核对附件名称及摘要；若 GitHub 未提供摘要，可将附件下载到新的临时目录后再计算比较。摘要一致只能证明下载内容匹配，不能证明作者身份或附件由标签构建。

  1. 在隔离环境或经用户同意的测试环境通过仓库名查找，检查预览中的仓库、标签、提交、摘要及文件。取消审核应不安装；确认后应从 GitHub 安装，支持自动启用的版本会启用并打开“已安装”，旧版需手动启用。验证实际执行。
  2. 已安装相同 ID 的本地副本不会自动变成 GitHub 来源；先保存需要的配置，再按发布说明处理，或使用隔离环境。已是相同 GitHub 版本且文件未变时，应用可能提示“已是最新版本”，不会重新显示安装预览。不要为测试擅自删除用户现有插件或设置。

3. 目录收录与网站一键安装

  1. 按收录流程提交 PR，说明仓库、Release、权限和测试结果。官网维护者可使用独立分支提交；第三方一般 Fork 官网仓库。PR 提交或预览部署成功不代表已收录。
  2. PR 合并后，等待网站部署及目录同步。核对网站能搜索到卡片，data-repository 与白名单一致，版本来自目录；在 catalog.json 中检查对应仓库、标签、提交和附件摘要。维护者可手动运行 Update plugin catalog；同步失败时查看 Actions 日志，不要手改生成的目录文件。
  3. 在安装了 QuickLauncher 的设备上，从网站点击“在 QuickLauncher 中打开”，允许浏览器打开应用，核对审核内容并由用户确认。检查插件启用状态，必要时手动启用，再重复直接输入和所需能力的实际测试。链接只能打开应用并发起审核，不会自动确认安装。

4. 遇到限流或版本暂不可用

GitHub 匿名 API 可能限流。可以等待额度恢复，再检查仓库和 Release；开发时使用已登录的 GitHub CLI 或授权的隔离测试请求可帮助排查，但 gh 登录不会自动为 QuickLauncher 配置认证，认证测试成功也不代表应用的匿名请求已恢复。不要在插件、网站、日志或 PR 中写入 Token。

网站卡片与目录同步、Pages 部署是不同步骤：卡片上线后版本仍可能暂不可用。同步约每四小时执行一次，网络故障、任务失败或部署延迟也会影响显示；核对正式 Release、白名单、Actions 状态与线上目录，目录超过 48 小时后应用会暂停使用。修复后重试同步与部署，再核对网站和应用。
