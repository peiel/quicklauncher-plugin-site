# QuickLauncher 插件开发

根据用户需求创建或修改 QuickLauncher 脚本插件。先阅读最新的[开发者指南](https://plugin.quicklauncher.flyee.tech/developer.html)，以其中的协议、限制和发布步骤为准；无法访问时说明限制，不要猜测未记录的宿主能力。先确定功能、触发词、输入输出、运行语言和是否需要读取选区；根据已有信息合理决定，不必要求用户填写所有项目。

## 开发和测试

- 插件目录根部需要 `manifest.json` 和清单中指定的入口脚本。使用稳定、唯一的插件 ID；触发词、运行环境、入口和输入类型遵循指南。优先选择目标环境可用的运行时，说明额外依赖及其安装方式。
- 用户执行插件时，应用通过标准输入发送一个协议版本为 1 的 JSON 对象；脚本只向标准输出写一个响应 JSON，并以成功状态退出。使用指南中支持的 `action`；不要把日志写入标准输出。校验输入，处理错误，遵守执行时间和输出大小限制。
- 需要选中文字时，在清单声明 `input: "arguments"` 和 `acceptsSelectedText: true`。只有用户无参数执行时应用才尝试将选区作为 `arguments` 提供，可能需要辅助功能授权，选区不可用时应提供明确提示或支持手动输入。不要声称插件可通过宿主 API 直接访问剪贴板、书签或使用历史。
- 需要输入触发词即预览结果时，可声明布尔字段 `previewOnKeyword: true`。插件启用后，输入完整触发词即自动运行；支持参数的插件也可在触发词后附加参数。`copy` 和 `copyAndShow` 的结果会明文显示在面板，用户回车复制当前显示的同一结果并关闭面板，不会再次运行脚本。预览文本最多 200 字符且不能含控制字符，其他动作不作为预览执行；预览不读取其他应用的选区。若结果是密码等敏感内容，应明确告知用户其会显示，并避免记录或上传。此功能需要支持该字段的新版 QuickLauncher；旧版仍按普通触发词执行。
- 需要无触发词输入预览时，可为 `input: "arguments"` 声明 `passiveTrigger`：类型为 `characterSet`，指定 1–128 个字符的 `allowedCharacters` 和 1–8 个非空 `requiredCharacterGroups`，每组最多 128 个字符且为允许字符的子集。匹配输入最多 256 UTF-8 字节；插件及被动开关均启用时，匹配输入可自动运行脚本并接收完整输入，只有 `copyAndShow` 结果可预览，用户确认后才复制。用户可在“设置 → 插件 → 已安装 → 对应插件设置 → 被动触发”查看规则并独立开关；关闭后仍可通过触发词执行。被动开关默认开启并在重启和插件更新后保留；支持安装后自动启用的 QuickLauncher 版本在用户确认安装后启用插件，旧版安装后需手动启用；支持保留启用状态的版本在审核确认更新后会保留更新前的启用状态，旧版更新后仍需重新启用。被动运行不会读取其他应用的选区。
- 被动匹配的脚本会在用户输入时自动运行，仍具有当前用户的文件和网络权限；不应在预览时产生副作用或上传输入，应明确说明数据用途并测试匹配与非匹配输入。
- 使用 `copyAndShow` 显示并复制普通结果；未启用触发词预览时，可用 `copy` 复制而不在面板显示敏感结果。一次性提醒通过 `scheduleReminder` 交给应用安排，不让脚本后台等待。根据需求选择动作，不要编造宿主 API。
- 脚本以当前用户身份运行，可能访问本机文件和网络。只请求功能所需的权限，说明数据如何处理；不要将凭据写入插件包，也不要未经用户授权上传选区或其他数据。
- 用代表性输入直接运行入口脚本，验证输出 JSON、错误处理和所需边界；文本涉及 Unicode、换行及 1024 UTF-8 字节限制时分别测试。对被动触发，验证匹配与不匹配输入，以及关闭后触发词仍可用、重新开启后预览恢复。对触发词预览，验证输入变化、无效参数和生成失败不会复制旧值，确认回车复制的是当前预览而不是重新生成的内容。给出本地导入和审查步骤，并说明旧版可能需要手动启用。真实的选区读取、通知和应用内行为需要在 QuickLauncher 中验证；不要把模拟标准输入或隔离测试当成真实界面和权限验证，未实际验证时明确说明。

## 按需发布和收录

只有用户要求时才准备 GitHub 发布或目录收录。在用户授权范围内操作：遵循指南创建公开仓库和正式 Release，使用公开打包工具生成唯一的 `.quicklauncher.json` 附件，并确认版本、标签和包内容一致。应用从 GitHub 获取插件并由用户审核安装；网站本身不托管插件包。

目录收录需要向[插件官网仓库](https://github.com/peiel/quicklauncher-plugin-site)提交 Pull Request：按指南更新仓库白名单和插件卡片，不手动修改自动生成的 `catalog.json`。提交 PR 不代表自动收录；发布、收录或测试未实际完成时如实说明。

按[完整验证与常见问题](https://plugin.quicklauncher.flyee.tech/developer.html#verification)核对标签、附件及 SHA-256，验证取消与确认安装、安装后的启用状态和执行，以及合并后的网站卡片、目录同步和一键安装；支持自动启用的版本确认安装后应启用，旧版可能需手动启用。保留用户已有插件及设置；同 ID 的本地副本和已是最新版本的 GitHub 副本可能影响安装审核测试，使用隔离环境或经用户同意处理。

GitHub 匿名请求可能限流。授权的 GitHub CLI 或隔离测试认证可用于排查，但不能证明应用的匿名请求已恢复，也不会自动配置应用认证。目录同步和网站部署可能有延迟；确认实际状态并区分已完成、待审核和待验证事项，不要暴露凭证。
